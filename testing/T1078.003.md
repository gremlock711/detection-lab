# T1078.003 — Valid Accounts: Local (backdoor admin)

## Atomic
#1 Create local account with admin privileges
  net user art-test /add
  net user art-test <pw>
  net localgroup administrators art-test /add

## New event source
First technique built on Windows Security log, not Sysmon.
  4720 account created  -> built-in rule 60109
  4732 admins changed   -> built-in rule 60154 (level 12)

## Field quirk
On 4732, targetSid = S-1-5-32-544 (the Administrators GROUP,
well-known SID), and the account added is in memberSid, not
targetUserName. targetUserName held "Administrators".

## My rule — correlation, not single-event
100105 (level 5): tags any account creation (if_group adduser)
100106 (level 13): fires only when 60154 (admin group change)
  follows a 100105 within 30s.
  Uses if_sid (child of 60154) + if_matched_sid (100105 preceded it).

Neither event alone is the attack — IT creates accounts, IT changes
group membership. The SEQUENCE within seconds is the backdoor.
That's what 100106 catches and what the built-in rules miss.

## Debugging
if_matched_sid + raw field-matching didn't work — the correlated
rule didn't have decoded win.eventdata fields available.
Fixed by chaining rule-to-rule (if_sid 60154) instead of
re-matching the event fields. Correlation rules chain built-in
rules; they don't re-parse events.
