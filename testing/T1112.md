# T1112 — Modify Registry (PowerShell logging disabled)

## Atomic
#33 — reg.exe writes 4 values under
HKCU\Software\Policies\Microsoft\Windows\PowerShell\
setting ModuleLogging, ScriptBlockLogging, Transcription,
EnableScripts all to 0

## Telemetry — the surprise
Expected Sysmon EID 13 (registry). Got nothing on an EID 13 search.
Found it on EID 1 instead: reg.exe process creation, with the full
reg add command in commandLine.
Lesson: reg.exe writes are visible as process creation even when
the registry event isn't where you expect.

Built-in rule 92041 also fired, labeled "Value added to registry key
has Base64-like pattern" — a heuristic misfiring on the value names.
Right alert, wrong reason.

## My rule
100102, level 12 (higher than persistence rules — disabling security
logging means someone is covering tracks)
Matched: image=reg.exe AND commandLine has "Logging" AND "/d 0"

## Known gap
Does not catch the Transcription write — value name is
"EnableTranscripting", no "Logging" substring. Deliberate:
adding a 4th condition would make the rule brittle. Two of the
three logging channels is enough to alert on the behavior.
