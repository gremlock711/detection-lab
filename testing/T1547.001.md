# T1547.001 — Registry Run Key Persistence

## Atomic
#1 Reg Key Run — reg.exe writes HKCU\...\CurrentVersion\Run\Atomic Red Team

## Telemetry
Sysmon EID 13 (registry value set)
Built-in rule 92302, groups: sysmon, sysmon_eid13_detections, windows
Key fields: targetObject, image (reg.exe), details

## My rule
100100, level 10, inherits sysmon_eid13_detections

## What broke
- if_group name changed in 4.9.2 (older docs say sysmon_event_13)
- backslash matching in <field> — could not get a path pattern to
  match across the separator. "CurrentVersion.Run." failed,
  "CurrentVersion" alone worked.
  Worked around with two separate field conditions, ANDed.
  OPEN QUESTION: revisit on T1112, also registry-based.
- lost ~1hr to a stale dashboard. rule was firing; search refresh
  wasn't enough, needed full page refresh.

## FP surface
OneDrive and Edge both have Run keys — they predate Sysmon install
so they don't appear in the window. On a real endpoint this rule
fires on installers and updaters. 1 event/24h here reflects an idle
lab box, not a tight rule.
