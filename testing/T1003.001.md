# T1003.001 — LSASS Memory (BLOCKED by Defender)

## Atomic
#2 Dump LSASS via comsvcs.dll
rundll32 C:\windows\System32\comsvcs.dll, MiniDump <lsass pid> full
Chose comsvcs (LOLBin, ships with Windows) over ProcDump/Mimikatz/
NanoDump which all require downloads. VM was isolated.

## Result: blocked at launch
"Access is denied" on process start. Confirmed NOT an elevation
issue — shell was High integrity (S-1-16-12288).
Defender ASR rule "Block credential stealing from LSASS"
(9e6c4e1f-7d60-472f-ba1a-a39ef669e4b2) killed it before rundll32
executed.

## The finding: block with no SIEM telemetry
Searched Sysmon/Wazuh after the block:
- targetImage *lsass*  -> nothing
- commandLine *comsvcs* -> nothing
- image *rundll32*      -> nothing

The process never launched, so Sysmon had nothing to record.

Defense-in-depth picture:
  Defender (EDR)     -> blocked it. worked.
  Sysmon -> Wazuh    -> saw nothing. gap.

If Defender were disabled or the technique altered to bypass ASR,
this attack would be INVISIBLE to the SIEM's rule-based detection.
The endpoint control was the only thing that caught it.

## Decision
Did not disable the ASR rule to force telemetry. Documented the
block as the result instead. In production the ASR rule IS the
detection for this technique — a Wazuh rule would be redundant
with, and weaker than, the control that actually stopped it.
