# T1055 — Process Injection (ran, SIEM blind)

## Atomic
#5 Read-Write-Execute injection (MockingJay / SecurityJoes).
Injector binaries shipped with ART, msys-2.0.dll vuln target
already on disk — ran fully isolated.
Uses LoadLibrary -> GetModuleInformation -> GetModuleHandleA ->
RtlCopyMemory -> CreateThread, deliberately avoiding VirtualAlloc /
WriteProcessMemory / CreateRemoteThread to evade API-sequence
heuristics.

## Result: succeeded, undetected
Notepad spawned = shellcode executed. Defender did NOT block it
(contrast T1003.001, which Defender killed at launch).

SIEM telemetry for the injection: none.
- EID 8 (CreateRemoteThread): no hits — technique avoids it by design
- injector process (searchVuln.exe / RWXinjectionLocal.exe): [fill
  in based on originalFileName search result]

## The theme across today
T1003.001 — Defender BLOCKED it, so no SIEM telemetry (stopped early)
T1055     — Defender ALLOWED it, and the SIEM still saw nothing
             (technique built to evade the events a SIEM watches)

Two different ways an attack ends up invisible to rule-based
detection. Neither is a gap in my rules — one is the endpoint
control doing its job, the other is a technique specifically
engineered to defeat behavioral logging. Detecting MockingJay
reliably needs memory scanning / EDR telemetry, not Sysmon
event rules.
